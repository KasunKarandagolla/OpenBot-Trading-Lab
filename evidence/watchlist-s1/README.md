# Session 1 work in progress — historical watchlist prototype

This is an incomplete research prototype, not the requested completed Session 1 foundation. It adds an append-only SQLite candidate and event history, multiple separate definitions for a symbol, a bounded 5m historical observation function, immutable events, idempotent repeated bars, gap/clock checks, terminal states, online SQLite backup, and explicit research-only states. `LIVE` monitoring is rejected until source identity and freshness can be checked. It has no order path and does not change the existing gate or scanner.

`historical-example.json` is a reproducible replay using case B01's sealed 5m FILUSDT export; `reproduce.py` verifies the inherited seal and bar hash and derives a prior 24-bar high/low before reading the subsequent 12 bars. Run `PYTHONPATH=scripts python3 evidence/watchlist-s1/reproduce.py` from the repository root. The casebook records the originating Binance archive and prior official checksum verification; this replay checks the sealed export, not the original archive. It uses previously studied development data and does not establish historical exchange eligibility, spread, a trade trigger, after-cost economics, or predictive value.

Commands: `PYTHONPATH=scripts python3 -m trading_lab.watchlist --root /tmp/your-local-runtime init` and `... list`. Other subcommands are `add`, `tick`, `history`, and `backup`; use `--help` for required arguments. Runtime files belong on a local Linux filesystem, never a shared Windows/WSL WAL directory. Use SQLite's backup API and preserve the original; restoration is not yet an operator command. The tick input is a raw JSON array of 5m bars, and its hash proves byte identity only: it does not prove symbol, venue, source authenticity, or freshness. Do not use it as live research evidence.
